# Clúster Raft en ESP32 + interfaz web — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Los 3 ESP32 forman un clúster Raft que replica eventos de botón y confirma alertas por mayoría, y un servidor Node en el 4.º PC muestra y controla todo en vivo.

**Architecture:** La lógica (Raft + máquina de estados sísmica + armado de JSON) es C++ puro sin Arduino, en `firmware/detector/src/`, y se prueba en el PC con `g++` contra una red simulada. `detector.ino` solo pega esa lógica al hardware: WiFi, UDP, HTTP, botón, LED, NTP, NVS y OTA. En el PC, `web/` tiene un sondeador que consulta a los nodos, un servidor HTTP con SSE y las dos vistas, adaptadas de los mockups.

**Tech Stack:** ESP32 Arduino core 3.3.12 (arduino-cli, FQBN `esp32:esp32:esp32`), ArduinoJson 7 (header-only, también en el PC), g++ con C++17, Node 22 sin dependencias npm (`node:http`, `node:test`, `fetch`).

**Spec:** `docs/superpowers/specs/2026-11-02-raft-esp32-design.md`

**Nota:** el proyecto no es un repositorio git. Los pasos de commit se omiten salvo que el usuario pida iniciar uno.

**Desviación del spec:** el PC no recalcula las alertas en JavaScript. Las toma de `/alertas` del nodo fuente, para no duplicar la regla en dos lenguajes. Siguen siendo datos de los nodos, así que se cumple el anti-objetivo.

## Global Constraints

- Nodos: nodo-1 `192.168.80.201`, nodo-2 `.202`, nodo-3 `.203`; gateway y DNS `192.168.80.1`, máscara `255.255.255.0`. WiFi `Apt_105` (clave en `config.h`, nunca en otros archivos).
- UDP Raft en el puerto `4210`; HTTP de cada nodo en el puerto `80`; servidor del PC en `0.0.0.0:8080`.
- Latido `300 ms`; elección aleatoria entre `1500` y `3000 ms`; máximo `8` entradas por `append` y ≤ 1400 bytes por paquete.
- Log en RAM con tope `1000` entradas; aviso en `900`; al llegar al tope se rechaza el evento y nunca se sobrescribe.
- Ventana de coincidencia `10000 ms`. Nivel `min(10, 1 + ms/450)`. Pulsaciones `< 80 ms` se ignoran.
- Niveles de alerta por promedio redondeado: `1–4 baja`, `5–7 media`, `8–10 alta`.
- `currentTerm` y `votedFor` en NVS (`Preferences`, namespace `raft`).
- `/estado` < 1 KB; `/log` de a máximo `50` entradas; se guardan los últimos `50` sucesos y los últimos `100` eventos.
- El PC sondea `/estado` cada `300 ms` con timeout de `250 ms`; tras `3` fallos seguidos el nodo es `inalcanzable`.
- Reintento de `forward` cada `500 ms`. NTP al arrancar y cada `10 min`; zona horaria `-5 h`.
- Nada que muestre la interfaz puede inventarse en el PC: todo sale de los nodos.

## Review Focus

1. **Un nodo se desenchufa mientras el PC espera su respuesta:** el panel lo marca inalcanzable a más tardar en 3 sondeos y los otros dos siguen actualizándose (Task 6, `poller: nodo colgado no frena a los demás`).
2. **Cambia el líder entre dos sondeos:** el PC pasa a leer el log del nuevo líder y, si el log de la nueva fuente es más corto que lo que ya tenía, lo vuelve a pedir desde 1 (Task 6, `poller: cambio de fuente recarga el log`).
3. **Se pierde el `forward_ack` y el seguidor reenvía, incluso a un líder nuevo:** el evento aparece una sola vez en el log (Task 4, `forward duplicado tras cambio de líder no duplica`).
4. **Se reinicia un nodo con el término guardado pero sin log:** se pone al día por lotes seguidos y sin esperar latidos (Task 4, `nodo reiniciado se pone al día en < 1 s simulado`).
5. **Un navegador se conecta en mitad de la sesión:** recibe al instante una foto completa por SSE, sin esperar el próximo cambio (Task 7, `sse: cliente nuevo recibe snapshot`).

### Task 2: Máquina de estados sísmica (`Sismo`)

**Files:**
- Create: `firmware/detector/src/nucleo/sismo.h`, `sismo.cpp`
- Test: `firmware/test/test_sismo.cpp`

**Interfaces:**
- Consumes: `Entrada`, `Evento` (Task 1).
- Produces:
  ```cpp
  struct Alerta { uint32_t id; float promedio; std::vector<std::string> eventos; uint32_t termino; int lider; };
  class Sismo {
   public:
    void aplicar(const Entrada& e);               // solo entradas confirmadas, en orden
    const std::deque<Evento>& eventos() const;    // últimos 100
    const std::vector<Alerta>& alertas() const;
    bool enAlerta(const std::string& idEvento) const;
    static int nivelPorTiempo(uint32_t ms);       // min(10, 1 + ms/450)
    static const char* nivelAlerta(float promedio); // "baja" | "media" | "alta"
    static uint64_t horaDe(const Evento& ev);     // t si != 0, si no t_lider, si no 0
  };
  ```

Regla de alerta, al aplicar un evento `E` con `horaDe(E) != 0`:
```
grupo = [E]
para cada detector D distinto de E.nodo (en orden 1,2,3):
   candidatos = eventos aplicados de D, sin alerta, con hora != 0, |hora - hora(E)| <= 10000
   si hay: agregar el más cercano a hora(E) (empate: el de menor índice de log)
si grupo tiene ≥ 2:
   inicio = min(hora de grupo); quitar del grupo los que tengan hora > inicio + 10000
   si sigue con ≥ 2: crear Alerta{id = E.indice de log, promedio, ids, termino, lider}
```
